◉ Git Routekaart

Bekijk de echte repository en speel daaronder de moderne git-werkstroom na: issue → branch → PR → merge → test → live.

Waarom drie omgevingen?

1 · Ontwikkel

Jouw branch, jouw machine. Hier bouw je, breek je en probeer je — fouten kosten hier niemand iets, want niemand anders draait deze code.

2 · Test

Een kopie van de echte omgeving. Elke merge naar main komt hier automatisch terecht. Fouten worden hier zichtbaar zonder dat gebruikers er last van hebben.

3 · Live

Het echte systeem, met echte gebruikers. Hier komt alleen een versie die op test al bewezen heeft te werken — en alléén via een bewuste, handmatige promotie. Nooit automatisch.

De kernregel: een merge mag nooit rechtstreeks live gaan. Probeer het rechts: merge een PR en kijk welke omgeving verandert.

Spiekbrief — wat doet elke merge-knop?

Merge commit

Alle commits van de branch blijven zichtbaar in de historie van main, plus één extra "overstapstation": de merge-commit met twee ouders. Volledige detailhistorie, maar de kaart wordt drukker.

Squash & merge

Alle branch-commits worden samengeperst tot één nieuwe commit op main. De losse tussenstops verdwijnen uit de main-historie: overzichtelijke rechte lijn, maar minder detail. De PR bewaart het detail wél.

Vuistregel die veel teams hanteren: squash & merge voor feature-branches met veel "wip"-commits, zodat main één commit per PR krijgt en de CI daar één versietag aan kan hangen.
